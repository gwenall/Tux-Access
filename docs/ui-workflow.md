# Desktop workflow

The Python/PySide6 desktop starts with **Your library**. Sign in with Native Instruments in your browser; after the private callback succeeds, the launcher automatically loads your account catalog. The signed-in account button shows a name initial, with **Switch account** and **Sign out** in its menu. Optional profile lookup runs on the account worker. The valid catalog is displayed before that lookup finishes; a failed profile lookup uses A and never discards the catalog. Names stay in memory, and remote avatar images are not downloaded. Sign out removes account rows, tokens, profile metadata and verified-download session data while retaining local installations and settings. **Settings → Advanced tools → Connect existing session** also refreshes the account catalog when an existing token is available. Settings contain paths and preferences, never credentials.

Supported products have one **Install** action. The coordinator selects a supported authorized installer, resolves its Metalink, downloads to the configured folder, checks its size and SHA-256, and installs the verified payload. The normal flow has no installer or destination picker. Every uninstalled row uses **Install**, directly dispatching its supported workflow. Products without a qualified adapter report that limitation inline; the row does not redirect to Settings. Original installer selection/download remains explicitly available in Advanced tools and selected product details. Native installed products also expose manual tools in selected details.

The footer and product row show actual worker stages. Download progress reports bytes received; verification and installation use an indeterminate indicator when no meaningful percentage is available. **Cancel** requests cleanup during cancellable work. Once the native pacman transaction starts, Cancel is disabled and the system authentication dialog may require attention. **Retry** repeats the failed operation. Closing requests cancellation and waits for the active worker to finish before closing.

Select a qualified local installation and use **Uninstall** in its details. The confirmation stays inside the main window and states that app files will be removed while saved projects, content and settings are retained. **Cancel** closes the confirmation without removing anything. During removal, verification can be cancelled; cancellation is disabled when the backend begins removing files or invokes pacman. Wine removal is limited to fully qualified managed records, and verified legacy experiments cannot be removed through this action. Native removal targets only the launcher's fixed package, retaining shared compatibility dependencies.

After removal, the library is rebuilt from account metadata and the backend's refreshed local records. Account products return to **Install**; purely local removed products disappear. If another verified copy remains, it stays launchable and the status explains that its source is shown in details. Wine's retained-data directory is displayed in the footer. A failed or cancelled removal refreshes actual remaining files before enabling another attempt. If the inventory cannot be checked, the UI says **Check state** and requires Refresh instead of claiming no installations remain. Refresh also works for local installations while signed out.

Successful file installation is labelled **Installed · activation unverified**. This does not establish successful application startup, NI account activation, support for other product versions, or DAW integration. The supported native Arch flows are Phasis and Reaktor 6. Managed Wine installation accepts only the exact artifacts and original payload layouts qualified by its backend adapters.

**All products**, **Applications**, **Ready to install**, **Installed**, and search filter the library. Applications shows known standalone application identities and verified local Wine applications, excluding library and expansion rows. Account refresh fetches authorized installer metadata once on its worker and adds bundle applications only when that metadata supplies their installers. Public product identities merge known account aliases with local installations; neutral application names do not assert a licensed edition. Installer references remain in memory and are excluded from catalog exports. If optional installer discovery fails, existing account products remain visible with a warning that bundle applications may be missing and Refresh can retry. The Applications filter does not change Ready or Installed semantics or claim that all applications have supported installation adapters.

Filtering and catalog reordering preserve product identity; hidden products have their selected details cleared until they are visible again. Installed shows validated local records. Locally installed native products show **Installed**; verified Wine applications switch their one row action to **Launch**. Details identify a managed prefix or a fully verified prior experiment. The Wine backend revalidates the selected known installation record before launching. Starting a process does not establish successful application startup, activation or audio compatibility. The account catalog stays intact when local installation records are merged. Startup checks, Refresh, and post-installation checks run on a worker rather than blocking the interface.

Settings is an embedded page in the main window, with no Settings popup. Paths are edited inline. Save persists preferences and returns to the library; Cancel discards unsaved edits. The shared progress and status footer remains visible in Settings and product options. Settings expose the download folder, application storage, Wine prefix base, Wine executable, optional yabridge directory, native preference, managed Wine toggle, and manual mode. Manual mode opens Advanced tools first while retaining supported automatic Install actions. Native Arch packages use fixed system locations. The content path is reserved for future library installers; Kontakt factory content stays in its original location inside the managed prefix. Advanced tools provide catalog import/export, reference-session connection, artifact metadata, manual installer selection, package inspection, installation of a Linux package verified during this launcher session, and asynchronous Wine diagnostics with suggested next steps.

The interface uses original typography and Qt widgets. It bundles no Native Instruments artwork, installers, signed URLs, callbacks, or account credentials.

**About**, immediately below Settings in the sidebar, opens an embedded page describing the independent, unofficial community project and its intent to help bridge the gap in NI Linux support. It states that the project is not affiliated with, endorsed by, or supported by Native Instruments, separates the launcher's MIT license from NI software licenses, and explains the prototype's qualified-product and runtime limitations. About opens no dialog or browser, keeps the library and in-memory account session intact, and leaves active jobs, progress and cancellation available in the shared footer. Returning through library navigation restores the current filter without changing the startup artwork.

## Verification

Run `QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -p 'test_*.py'` with the desktop extra installed. UI tests mock all account, coordinator, and installation operations. They check automatic account refresh, one-button worker dispatch without pickers, thread separation, status preservation, native transaction cancellation boundaries, error redaction, retry, and the digest requirement for the advanced manual installer.

Sign-in uses an embedded banner above the main pages, with browser instructions, Cancel sign-in and inline retry after failure. No authentication dialog is created and no modal event loop runs. Browser return starts the token exchange on a worker, then refreshes the catalog. Cancellation and app closure release the private callback receiver and clear pending verifier/code values. The toolbar refresh action uses a circular-arrow icon with a Refresh library tooltip and accessibility name.
